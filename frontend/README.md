# Лабораторна робота №4 - Інтеграція фронтенду з бекендом

## 1. Як запустити проект

Для зручності управління проєктом використовується пакет `concurrently`, який дозволяє запускати фронтенд та бекенд одночасно однією командою з кореня проєкту.

### Режим розробки 

1. Відкрийте термінал у кореневій папці проєкту.
2. Встановіть залежності (якщо ви робите це вперше):
   `npm install` (в корені, у папці backend та frontend)
3. Запустіть проєкт:
   `npm start`

### Режим розробки 
Цей режим компілює TypeScript у чистий JavaScript та запускає файли. Для запуску вам знадобляться два окремих термінали.

1. Відкрийте перше вікно терміналу, перейдіть до папки з бекендом та виконайте 

`npm install` (Залежності)

`npm run build` (Компіляція у папку dist)

`npm run start` (Запускає скомпільований сервер)
 
 Базова адреса сервера: http://localhost:3000/api/v1
2. Запуск фронтенду. Відкрийте новий термінал і перейдіть до папки з фронтендом та виконайте

`npm install`

`npm run build`

`npm run serve`

Після успішного виконання цих команд ваш додаток буде доступний у браузері за адресою: http://localhost:8080

## 2. Сценарії перевірки (Test Cases)
- **GET (Список і пагінація):** Відкрийте головну сторінку, змініть категорію або скористайтеся пошуком. Також перевірте клік на стрілочку сортування дати.
- **POST/PATCH (Створення та редагування):** Увійдіть під будь-яким ID. Створіть пост. Перевірте, що він миттєво з'являється у списку. Відкрийте деталі посту і спробуйте змінити текст.
- **Помилки:** 1. Вимкніть бекенд і оновіть сторінку фронтенду. UI покаже зрозумілу помилку "Помилка мережі або CORS", а не білий екран.
  2. Спробуйте створити пост з порожнім заголовком — спрацює валідація.

## 3. Правила версійності та контрактів (DTO)
У цьому проєкті дотримується принцип «не ламати формат»:
- Усі ендпоінти використовують версіювання: `/api/v1/...`.
- **Заборонено:** перейменовувати або видаляти існуючі поля в DTO `PostViewDto` та `CommentViewDto`, зміна типів даних (наприклад, `id` з `string` на `number`).
- **Дозволено:** додавати нові необов'язкові поля.
