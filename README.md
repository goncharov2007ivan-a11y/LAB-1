# Дошка оголошень 

## Основний функціонал
- **Автентифікація та Авторизація:** Безпечна реєстрація та вхід за допомогою JWT (JSON Web Tokens). Хешування паролів через `bcrypt`.
- **Управління оголошеннями (CRUD):** Створення, читання, редагування та видалення постів. Зміна даних доступна лише авторам (захист від IDOR).
- **Система коментарів:** Можливість коментувати оголошення. Каскадне видалення коментарів при видаленні поста.
- **Фільтрація та Пагінація:** Сортування постів за категоріями та розбиття на сторінки.
- **Клієнтська та Серверна валідація:** Синхронізована перевірка даних за допомогою `Zod`.

### Backend (API)
- **Node.js & Express:** Побудова RESTful API.
- **TypeScript:** Строга типізація бізнес-логіки.
- **SQLite 3:** Легковагова реляційна база даних.
- **Zod:** Валідація схем даних.
- **jsonwebtoken & bcrypt:** Криптографія та захист сесій.

### Frontend (SPA)
- **HTML5 & CSS3:** Семантична розмітка та адаптивний дизайн без використання UI-фреймворків.
- **TypeScript (ESModules):** Модульна архітектура клієнтської логіки.
- **DOM API:** Пряма маніпуляція DOM-деревом (безпечний рендеринг через `textContent` для захисту від XSS).
- **Fetch API:** Асинхронна взаємодія з бекендом.

## Як запустити проект

Для зручності управління проєктом використовується пакет `concurrently`, який дозволяє запускати фронтенд та бекенд одночасно однією командою з кореня проєкту. Встановіть залежності:
Переконайтеся, що ви знаходитесь у кореневій папці проєкту (`LAB-1`), і виконайте команду, яка автоматично встановить залежності для кореня, бекенду та фронтенду:
   ```bash
   npm run install-all
   ```
   - Створіть файл `.env` у папці `backend` і додайте секретний ключ для генерації токенів, зробіть це в будь - якому випадку:
     ```env
     JWT_SECRET=your_super_secret_key_here
     ```
   Після цього виконайте:
   ```bash
   npm run start
   ```
#### Плюси 
- **Швидкість запуску**, не треба розгортати 3 окремі термінали

#### Мінуси

- **Дуже швидко** забивається термінал, усі логи від бекенду, компілятора TS та самого сервера будуть сипатися в 1 вікно.
- Якщо треба вимкнути, наприклад, сервер бекенду, то доведеться вимикати все разом.

### Режим розробки (Ручний запуск у 3 термінали) 
 
Цей режим ідеально підходить для розробки та дебаггінгу, оскільки логи кожного процесу виводяться окремо, що дозволяє швидко знаходити помилки. Для запуску вам знадобляться три окремі вікна терміналу.

#### 1. Термінал 1: Запуск Бекенду
Відкрийте перше вікно терміналу, перейдіть до папки `backend` та виконайте команди:
```bash
cd backend
npm install
npm run build
npm run start
```
Базова адреса сервера: http://localhost:3000/api/v1

#### 2. Термінал 2: Компілятор фронтенду
Відкрийте друге вікно терміналу, перейдіть до папки `frontend` і запустіть TypeScript компілятор у режимі спостереження (він буде автоматично перекомпілювати .ts файли при кожному збереженні):
```bash
cd frontend
npm install
npx tsc -w
```
Не закривайте цей термінал, він має працювати у фоні.

#### 3. Термінал 3: Cервер фронтенду
Відкрийте третє вікно терміналу, також у папці `frontend` та локальний веб-сервер для відображення HTML та скомпільованого JS:
```bash
cd frontend
npm run serve
```
(Примітка: якщо npm run serve не налаштовано, використовуйте npx http-server . -p 8080)

Після успішного виконання цих команд ваш додаток буде доступний у браузері за адресою: http://localhost:8080

## Безпека
У проєкті реалізовано захист від найпоширеніших веб-уразливостей:
- **SQL Injection:** Використання виключно параметризованих запитів на рівні драйвера БД.
- **XSS (Cross-Site Scripting):** Дані від користувачів рендеряться як текст, що унеможливлює виконання ін'єктованих скриптів.
- **Broken Access Control (IDOR):** Кожна операція зміни або видалення суворо перевіряється через `userId`, розшифрований з JWT на сервері.
- **Security Missconfiguration:** Налаштований CORS та заголовки відповіді.
